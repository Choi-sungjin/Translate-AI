# v1.3.0 번역 모델 선택과 비교

측정일: 2026-10-18. 현재 PC의 ChatGPT 로그인과 공식 Codex CLI 0.162.1을 사용했습니다. API 키를 사용하지 않았습니다.

## 선택 방법

- 확장 팝업의 **ChatGPT 번역 모델**을 바꾸면 자동 저장됩니다.
- 전체 설정 화면에서도 모델을 선택하고 **설정 저장**을 누를 수 있습니다.
- GPT-6.1 Sol, GPT-6 Luna, GPT-5.6 Luna를 지원합니다. 모두 추론 강도 `low`로 실행됩니다.
- 다음 번역 요청부터 적용됩니다. 이미 번역한 페이지 전체를 새 모델로 읽으려면 원문으로 복원한 뒤 페이지 번역을 다시 시작하세요.
- 번역 캐시와 문단 묶음은 모델별로 분리됩니다. 모델 사용 권한이 없거나 로컬 연결 프로그램이 오래된 경우 오류를 표시하며 다른 모델/서비스로 자동 전환하지 않습니다.
- 기존 설정의 기본 모델은 이전에 실제 사용하던 GPT-6.1 Sol입니다. 속도를 원하는 사용자는 GPT-6 Luna를 우선 시험할 수 있습니다.

기존 설치 업데이트: [Windows 재시작 보완판](LAUNCHER-UPDATE-1.3.0.md)을 적용하고 로컬 연결 프로그램을 재시작합니다. 확장이 구버전이면 Chrome/Comet 각각의 확장 관리 화면에서 Translate AI를 새로고침한 다음 대상 웹페이지도 새로고침하세요. 연결 코드 불일치 오류가 나오면 연결 화면을 새로고침하고 현재 코드를 각 브라우저의 확장 설정에 다시 저장하세요.

## 실제 속도

각 모델에 같은 자료를 주고 입력 번역 3회, 문단 3개 묶음 번역 3회를 측정했습니다. 아래 값은 중앙값이며 괄호는 최솟값~최댓값입니다.

| 모델 | 한국어 입력 → 영어 | 영어 문단 3개 → 한국어 | Sol 대비 중앙값 소요 시간 감소 |
|---|---:|---:|---:|
| GPT-6.1 Sol | 7.53초 (6.39~8.60) | 8.70초 (8.66~8.77) | 기준 |
| GPT-6 Luna | **5.68초** (5.39~6.94) | 6.75초 (6.53~8.25) | 입력 24.6%, 문단 22.4% |
| GPT-5.6 Luna | 6.00초 (5.19~8.29) | **6.01초** (5.88~6.95) | 입력 20.3%, 문단 30.9% |

각 모델의 준비 호출 1회는 제외했습니다. 라운드마다 모델 순서를 회전했고, 호출은 순차 실행했습니다. 확장/브리지 결과 캐시를 거치지 않았습니다. 시간에는 로그인 상태 확인과 CLI 프로세스 시작이 포함되며 공급자의 프롬프트 캐시는 통제하지 못했습니다. 전체 웹페이지 완료 시간 또는 순수 모델 생성 속도를 측정한 것은 아닙니다.

표본이 모델·방식당 3개로 작고 범위가 겹칩니다. 이번 자료에서는 입력은 GPT-6 Luna, 문단 묶음은 GPT-5.6 Luna가 가장 빨랐으며 모든 상황에서 같은 순위를 보장하지 않습니다. 다른 모델이 더 빠를 가능성도 이번 검사로 배제할 수 없습니다.

재현: `npm run benchmark:models`. 실제 계정 사용량을 소비하며 생성된 `artifacts/model-benchmark-1.3.0.json`에 요청 자료·번역문·측정값이 저장됩니다. [이번 원자료](benchmarks/model-benchmark-1.3.0.json).

## 번역 품질 검토

모델당 서로 다른 12개 항목(입력 3개, 문단 9개)의 결과를 모두 검토했습니다. 확인 기준은 핵심 의미·부정/조건, 숫자/단위/식별자, 기술 용어, 관용 표현, 목록 순서 및 인용 지시문 처리입니다. 정답 번역과의 자동 점수나 독립적인 사람 평가가 아닌 이 작업에서의 정성적 검토입니다.

- 세 모델 모두 18개의 측정 호출을 합쳐 오류 없이 완료했습니다. 숫자·단위·파일명·경로·환경 변수·목록 순서가 유지됐고, 문서 안의 인용된 지시문을 명령으로 실행하지 않고 번역했습니다.
- GPT-6.1 Sol과 GPT-6 Luna는 이 자료에서 핵심 의미가 잘 유지됐습니다. 출시 보류, 문제 해결, 진행 승인 등의 관용 표현도 자연스럽게 옮겼습니다. 이 작은 자료로 두 모델의 전반적인 품질이 같다고 판단할 수는 없습니다.
- GPT-5.6 Luna에는 약점이 있었습니다. “does not necessarily mean”을 “의미는 아닙니다”로 옮겨 **반드시 그렇다는 것은 아니다**라는 한정이 약해졌습니다. “Source the local ROS 2 environment”를 “로컬 ROS 2 환경을 소스하세요”로 옮긴 표현도 다른 두 모델의 “환경을 불러오세요”보다 부자연스러웠습니다. “publishes”는 “게시”보다 ROS 문맥의 “발행”이 더 적합합니다.

이번 결과에서는 **GPT-6 Luna를 속도와 품질의 균형을 위한 우선 선택**으로 제안합니다. GPT-5.6 Luna는 문단 묶음에서 더 빨랐지만 부정문·기술 설명의 표현을 확인하며 쓰는 편이 좋습니다. Sol이 더 높은 품질을 보일 수 있는 복잡한 문맥은 별도 자료로 비교해야 합니다.

OpenAI는 [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)를 집중된 반복 작업용 모델로 설명합니다. [Codex 모델 문서](https://learn.chatgpt.com/docs/models)의 모델 제공 범위는 계정과 클라이언트에 따라 달라질 수 있습니다. 위 속도와 품질 판단의 근거는 공식 설명이 아니라 이 PC에서의 실제 측정입니다.

## 검증 범위

- JavaScript 구문 검사, 단위 검사 20개, 확장을 실제 로드한 모의 API 회귀 검사 25개 통과.
- 격리된 Chrome for Testing에서 실제 ChatGPT 로그인으로 두 Luna 모델을 각각 선택·저장·재로드하고 페이지 병기, 스페이스 3회 번역, 입력/페이지 원문 복구를 확인했습니다.
- 사용자의 설치된 Chrome/Comet 검증 결과는 적용 후 별도 기록합니다. 격리된 시험 브라우저 결과를 사용자 브라우저 검증으로 간주하지 않습니다.
