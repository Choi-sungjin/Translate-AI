# Windows 연결 프로그램 재시작 보완

2026-10-18: 설치된 Chrome·Comet 확장은 모두 v1.3.0이었고, 두 브라우저의 팝업에서 GPT-6 Luna 선택과 저장 완료를 확인했습니다. 그러나 로컬 연결 프로그램은 v1.2.0 프로세스가 그대로 남아 있었습니다. Chrome의 실제 NVIDIA 검색창에서 스페이스 3회는 인식됐지만 연결 프로그램 업데이트 오류가 표시됐으며 입력 원문은 보존됐습니다.

기존 `Start-Translate-AI.cmd`는 실행 중인 연결 프로그램의 이름만 확인해 구버전도 준비 완료로 표시할 수 있었습니다. 첫 재시작 보완판에서도 사용자가 실제 실행한 결과 `No launcher-owned bridge process was recorded.`가 나왔고, 구버전이 그대로 남았습니다. 중지 코드가 PID 파일에만 의존했기 때문입니다. 점검 환경에는 PID 파일이 있었으므로 사용자 실행에서 기록을 찾지 못한 정확한 이유는 아직 확인되지 않았습니다.

두 번째 보완판(r2)은 PID 기록에 의존하지 않고 `127.0.0.1:18458`의 실제 리스너를 먼저 조회합니다. 프로세스 이름이 `node.exe`이고 이 프로젝트의 `bridge/server.mjs` 경로가 명령행의 완전한 인수와 일치할 때만 중지합니다. 리스너가 없을 때는 기록된 PID를 같은 방식으로 검증합니다.

## 적용

1. Git 작업 폴더는 최신 `main`으로 업데이트합니다. 최초 v1.3.0 ZIP 설치는 릴리스의 `Translate-AI-1.3.0-launcher-update-r2.zip`을 기존 설치 폴더에 덮어 풉니다. 기존 파일을 삭제하거나 연결 코드를 다시 저장할 필요는 없습니다.
2. Windows 파일 탐색기에서 **`Restart-Translate-AI.cmd`를 더블클릭해 실행**합니다.
3. 검은 창에 **`READY: Translate AI bridge v1.3.0, model selection enabled.`**가 나오면 연결 프로그램 재시작이 확인된 것입니다. 오류이면 창의 메시지를 확인하세요.
4. 이미 v1.3.0으로 새로고침한 확장은 다시 새로고침하지 않아도 됩니다. 대상 웹페이지에 최신 확장 코드가 로드돼 있어야 합니다.

## 변경과 검증

- 시작 시 확장 manifest와 실행 중인 연결 프로그램 버전이 다르면 명확한 오류를 표시합니다.
- 재시작은 실제 리스너 또는 기록된 PID의 프로젝트 경로를 검증하고 종료를 기다립니다. 다른 앱, 다른 프로젝트, 여러 리스너, 처리 중인 번역은 재시작을 중단합니다. 경로 앞부분만 같은 다른 파일도 거절합니다.
- 재시작 결과 창을 유지하고 `%LOCALAPPDATA%\Translate-AI\restart-status.json`에 단계·시간·오류·상태 저장 경로를 기록합니다. 인증 정보나 번역 원문은 기록하지 않습니다.
- Windows PowerShell 5에서 모의 검사 12개 통과: 기존 8개(구버전, 다른 앱 포트, 현 버전 재사용, 번역 중, 다른 PID, 정상 재시작, PID·리스너 없음, 잘못된 재시작 버전)와 추가 4개(PID 기록 없이 실제 리스너 재시작, 다른 프로젝트 리스너 거절, 유사 경로 거절, 여러 리스너 거절).

이 실행 파일 검사는 실제 사용자 프로세스를 재시작한 증거가 아닙니다. 설치된 두 브라우저의 Luna 번역·복구 최종 검증은 로컬 연결 프로그램의 성공적인 재시작 후 진행합니다. 기존 확장 v1.3.0 파일과 원래 릴리스 ZIP은 변경하지 않습니다.
